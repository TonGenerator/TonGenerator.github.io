# GENERATOR TON USERNAME

Публикация на GitHub Pages, адрес `tongenerator.github.io`, загрузка Windows ZIP в Releases и подключение Google / Яндекс: [DEPLOY-GITHUB.md](DEPLOY-GITHUB.md).

На сайте и в Windows-приложении можно указать до 32 шаблонов через запятую или с новой строки, например `_GAY, _LOX`. Каждый вычисленный адрес проверяется сразу по всем оставшимся шаблонам, без разделения потоков между ними. После совпадения приложение сохраняет зашифрованный результат и продолжает с оставшимися целями; в браузере результаты остаются в памяти до скачивания отдельных секретных JSON. Если один адрес подходит нескольким шаблонам, они засчитываются вместе. Не закрывай вкладку без резервных копий. Оценка времени до ближайшего совпадения учитывает объединённую вероятность, включая пересекающиеся шаблоны.

В интерфейсе один выбор: **CPU / GPU / CPU + GPU / MAX**. Обычные режимы Windows автоматически освобождают ресурсы для других программ. Нормальная активность диска не останавливает поиск. При почти полной занятости диска и высокой задержке срабатывает краткая пауза; задержки управляющего цикла и CPU/GPU-нагрузка также учитываются. **MAX** включает CPU + GPU со всеми потоками и 100% программной активности GPU, отключая автоснижение. Он может мешать играм и работе; аппаратные ограничения и время CPU-проверки всё равно влияют на фактический процент загрузки. Ручная пауза и сон продолжают работать.

В консоли MAX включается флагом `--max`, например `./generator-ton --wallet telegram --pattern ton --engine hybrid --max`. В Colab есть такой же переключатель. Пауза и остановка остаются доступны.

В трее: **Пауза поиска / Продолжить поиск**, **Остановить поиск**, автозапуск, **Удалить приложение…**, выход. Удаление запускается только после подтверждения: убирает автозапуск, ярлык и неизменённые файлы из манифеста установки. Кошельки и настройки в `%APPDATA%` сохраняются. Имя и значок EXE заменяют стандартные метаданные Electron. Для ZIP релиза: `npm run build`, затем `npm run desktop:package -- --zip` (Windows, локальный закреплённый Electron runtime и Python 3).

На сайте кнопка **«Установить»** открывает гайд Linux: скачивание исходников, установка CPU / CPU + GPU, безопасные команды клонирования GitHub и копирование в буфер. `npm run build` собирает также страницу установки и ZIP исходников для скачивания. Архив включает только исходные файлы, без кошельков, ключей, локальных зависимостей и runtime.

## Google Colab — панель с кнопками

В разделе **Установить → Google Colab** скачай блокнот `GENERATOR_TON_USERNAME_Colab.ipynb` и ZIP исходников. В [Colab](https://colab.research.google.com/) выбери **Файл → Загрузить блокнот**. Для GPU сначала выбери **Среда выполнения → Сменить среду выполнения → GPU**. Запусти ячейку ▶ и выбери ZIP исходников; вместо ZIP можно указать публичный GitHub в поле ячейки.

Панель поддерживает Telegram WalletTg, Tonkeeper V4/V5, CPU / GPU / CPU+GPU, настройки нагрузки, короткий тест, полный поиск, паузу и остановку. Нажми **Подготовить среду**, затем **Тест скорости** или **Начать поиск**. Видны число проверок, скорость, время поиска, ожидаемая дата нахождения и даты для вероятностей 50% / 95%. По умолчанию UTC+7; часовой пояс меняется. Даты пересчитываются по текущей скорости, пауза приостанавливает оценку; прошедшее время не вычитается из ожидания случайного совпадения. У короткого теста показаны дата остановки и оставшееся время.

Найденный кошелёк сохраняется до уведомления о результате. **Архив с ключом** скачивает зашифрованный JSON вместе с `recovery.key`. Для импорта отметь **Скачать открытые слова для импорта** и нажми **Слова (JSON)**: это отдельный секретный файл, его содержимое не выводится в ячейки. Повторный запуск ячейки показывает прежнюю панель, сохраняя текущий поиск и доступ к результатам. Перезапуск или отключение среды может удалить их.

**Это облако Google, а не локальная генерация.** Не загружай существующие сид-фразы. Архив содержит ключ расшифровки и даёт доступ к кошельку, храни его офлайн и не публикуй. Перед публикацией блокнота очисти вывод ячеек с адресами и настройками. [GPU, продолжительность и лимиты Colab меняются](https://research.google.com/colaboratory/faq.html). Ускоритель NVIDIA сам по себе не гарантирует доступ к WebGPU/Vulkan, который использует этот движок: подготовка проверяет GPU и сообщает, если нужен CPU. Linux GPU в реальной Colab-среде этой сборкой не замерялся; скорость не обещается. Новые драйверы NVIDIA и обход ограничений сервиса не устанавливаются.

Для разработчика: исходники панели находятся в `colab/`, `npm run colab:build` обновляет блокнот, `npm run source:package` собирает также ZIP. `python -m unittest discover -s tests -p test_colab.py` проверяет контроллер, паузу/остановку, восстановление результата и календарные оценки.

## Ubuntu / Debian / Linux — запуск в терминале

После загрузки исходников с GitHub:

```bash
git clone <URL_ТВОЕГО_РЕПОЗИТОРИЯ> generator-ton-username
cd generator-ton-username
bash scripts/install-linux.sh
./generator-ton --pattern _FURRY --wallet telegram
```

В первой строке замени `<URL_ТВОЕГО_РЕПОЗИТОРИЯ>` ссылкой своего репозитория. Установщик использует существующий Node.js 22+ либо скачивает Node.js 24 LTS с nodejs.org в локальную `.runtime/` и проверяет SHA256 по официальному манифесту. Системный Node не заменяется; sudo для установки самого генератора не нужен. Нужны git, curl, ca-certificates, tar и xz (на Ubuntu/Debian: `sudo apt-get install git curl ca-certificates xz-utils`). Поддерживаются Linux x64/arm64.

Если Node.js 22+ уже установлен, достаточно:

```bash
npm ci
npm run cli -- --pattern _FURRY --wallet telegram --threads 8
```

Работает без браузера и открытых портов. Есть Telegram WalletTg, Tonkeeper V4R2/V5R1, новые фразы и стандартный walletID для импорта. `--wallet v4` или `--wallet v5` переключает контракт; `--ignore-case` отключает регистр; `--words 24` выбирает классическую TON-фразу для V4/V5. По умолчанию — 12 слов BIP39. Консоль показывает проверенные адреса, текущую скорость и среднее ожидание; `--json` выдаёт также сроки для 50%/95%. Поиск случайный, срок не гарантирован. Ctrl+C останавливает процесс; повторный запуск продолжает независимый случайный поиск, обходить прежние варианты не требуется.

`--threads auto` по умолчанию использует половину доступных CPU-потоков; можно явно указать до 256. `--cpu-load 90` задаёт максимум активности, внешний CPU и задержки снижают её автоматически, при сильной нагрузке включается пауза. Процесс получает пониженный приоритет, если ОС разрешает. Linux CLI не обнаруживает игры и внешнюю загрузку GPU как Windows-приложение: для GPU действует заданный лимит. `--duration 30` выполняет короткий замер и завершает процесс.

### GPU в консоли (дополнительно)

```bash
bash scripts/install-linux.sh --gpu
./generator-ton --pattern _FURRY --wallet telegram --engine hybrid --threads 8 --gpu-load 70
```

При обычной установке CPU GPU-пакет не скачивается. Для GPU используется необязательный [webgpu / Dawn](https://github.com/dawn-gpu/node-webgpu), закреплённый на 0.6.2. Нужен совместимый GPU и рабочий драйвер, на Linux — поддержка Vulkan. Варианты: `--engine gpu` и `--engine hybrid` (CPU + GPU); проверяющие GPU-потоки входят в общий `--threads`. GPU поддерживает 12 слов BIP39, проходит контрольный тест и каноническую проверку результата. `--gpu-load 5..90` — программная доля работы, не обещание такого же процента в диспетчере. Длинные команды останавливают GPU; явное `--ignore-gpu-limit` разрешает их. При отказе GPU hybrid продолжает CPU-поиск. Для ручной установки модуля при готовом Node: `npm install --no-save --package-lock=false webgpu@0.6.2`.

### Результаты и перенос

По умолчанию файлы хранятся в `~/.generator-ton-username/wallets/`, вне репозитория. `--output /путь/к/папке` меняет папку. Сид-фразы не печатаются в stdout/stderr/JSON-прогресс. Результат сохраняется как `wallet-….encrypted.json` с AES-256-GCM; рядом создаётся случайный `recovery.key`. На Linux новые файлы получают права 600, каталог — 700. Публичные метаданные также защищены от изменения. Сохрани **и зашифрованный файл, и recovery.key**: без ключа восстановление невозможно. Ключ в этой же папке защищает от случайного раскрытия JSON, но не от того, кто получил доступ ко всей папке или твоему пользователю ОС.

Явный экспорт для импорта в кошелёк:

```bash
./generator-ton export \
  --file ~/.generator-ton-username/wallets/wallet-ИМЯ.encrypted.json \
  --output SECRET-TON-backup.json
```

Экспортированный JSON содержит открытые слова. Консоль выводит только путь; файл не перезаписывается. При переносе ключа отдельно укажи `--key /путь/recovery.key`. Эти файлы, локальный runtime и результаты тестов исключены из Git и Docker-контекста. Не загружай секретные копии или ключ в GitHub вручную. Запуск поиска не обращается к блокчейну, не разворачивает контракт и не отправляет средства.

### Docker (CPU)

```bash
docker build -t generator-ton .
docker run --rm -it -v generator-ton-data:/data generator-ton \
  --pattern _FURRY --wallet telegram --threads 8 --output /data
```

Результаты и ключ остаются в томе `generator-ton-data`. Порты не публикуются. Для разработчиков: `npm ci && npm run build && npm test`. Workflow GitHub Actions проверяет Ubuntu 24.04 и Windows на Node.js 22/24. Локальные CLI-тесты также запускаются на настоящем Linux (Debian/WSL); это не заменяет проверку каждой версии драйвера GPU.

## Приложение Windows

Готовая папка EXE-сборки поставляется отдельно; архив исходников для GitHub содержит CLI и исходный код Windows-приложения.

Запуск: `release/GENERATOR TON USERNAME/GENERATOR TON USERNAME.exe`. Интерфейс открывается на **http://127.0.0.1:11111/**. Папка приложения должна оставаться целой: EXE использует соседние файлы. При первом обычном запуске создаётся ярлык в меню «Пуск» и включается автозапуск текущего пользователя. Приложение запускается в трее после входа в Windows; незавершённый поиск возобновляется, если эта настройка включена. После найденного адреса поиск останавливается.

Закрытие браузера не завершает вычисления. В трее доступны открытие интерфейса, пауза, автозапуск и выход. Максимумы CPU/GPU задаются в интерфейсе. Авторежим повышает скорость по свободным ресурсам даже во время обычной работы за ПК; движения мыши больше не ограничивают поиск двумя потоками и 5% GPU. Внешняя нагрузка CPU и GPU снижает соответствующий бюджет сразу, восстановление постепенное. Для активной работы оставляется запас CPU; процессы генератора имеют пониженный приоритет. Задержка управляющего цикла также снижает нагрузку, но не измеряет FPS других программ. При обнаружении известной игры, эксклюзивного Direct3D/полноэкранного режима, очень высокой внешней нагрузки или работы от батареи вычисления ставятся на паузу. После игры выдерживается 20 секунд, после кратковременной перегрузки — 3 секунды. Обнаружение обычно занимает 1–3 секунды; нулевое влияние на FPS во всех играх не гарантируется. Если монитор Windows перестал отвечать, поиск приостанавливается.

Найденные результаты автоматически сохраняются **зашифрованными Windows DPAPI** в папке данных приложения текущего пользователя. При нахождении появляется уведомление Windows; во время игры уведомление откладывается. История доступна в интерфейсе после перезапуска. Для переноса на другое устройство сохрани секретный JSON: защищённая папка приложения не заменяет переносимую резервную копию. DPAPI защищает от других пользователей, но не от вредоносной программы с доступом к текущей учётной записи.

Основной процесс, вычислительный браузер и UI разделены. Вычислительный браузер не имеет Node API и сетевых соединений. Локальный HTTP API слушает только 127.0.0.1:11111, проверяет Host, Origin, cookie-сессию и CSRF. Публичный статус не содержит слов. Расшифровка и скачивание слов доступны только по действию пользователя. Источник случайности и параметры импорта не изменены.

Сборка: `npm run build`, затем `npm run desktop:package`. Используется официальный Electron 45.0.0; архив проверяется по SHA-256 из официального GitHub manifest. Монитор Windows компилируется системным C#-компилятором; дополнительных библиотек в npm не добавлено. Подробности: `audit/WINDOWS-APP.md`.

## Tonkeeper

Выбери V4R2 или V5R1. По умолчанию создаются **12 слов BIP39**, ключ по пути `m/44'/607'/0'`, стандартный walletID и адрес выбранной версии. При импорте в актуальный Tonkeeper выбери 12 слов и ту же версию V4/V5. Можно выбрать классические **24 слова TON**, но их генерация существенно медленнее.

Слова, случайно подходящие одновременно под TON и BIP39, отбрасываются при проверке победителя: автоматическое распознавание схемы не должно открыть другой адрес. В тестах адрес заново восстанавливается из слов и сверяется с TON SDK.

**Перебор walletID в интерфейсе отключён.** Tonkeeper при обычном импорте не принимает произвольный ID. Сменой экспорта или ссылкой исправить это нельзя. Прежние результаты с нестандартным ID требуют отдельного клиента/SDK; они не превращаются в совместимые результаты Tonkeeper. Исходный алгоритм оставлен для старых вкладок и воспроизводимых сравнений.

Поддержка BIP39 и стандартных ID проверена по официальным исходникам Tonkeeper Android и Web. Импорт в установленное приложение в этой сессии не выполнялся. Источники и границы проверки: `audit/NEW-WALLET-SECURITY.md`.

## Telegram WalletTg

Это отдельный контракт. Выбери Telegram: создаются 12 слов BIP39, Mainnet, UQ, фиксированный ID Telegram, без ротации ключа. В Telegram нужен импорт другого кошелька, а не восстановление уже выбранного адреса. Формат и адрес сверены с официальным кодом; приём нового неразвёрнутого кошелька сервером Telegram в этой сессии не проверялся. V4/V5 в WalletTg с сохранением адреса не преобразуются.

## Поиск и скорость

Каждый адрес в текущем интерфейсе соответствует новой фразе и стандартному ID. Счётчик отражает проверенные адреса. Среднее время не является гарантированным сроком. Начало ищется после первых четырёх символов; окончание включает CRC16. Начни с 2–3 символов.

CPU использует Web Workers, локальную libsodium/WebAssembly для Ed25519 и параллельного PBKDF2 BIP39, предварительную проверку битов хеша и повторно используемые буферы SHA256. Каноническая проверка победителя остаётся отдельной. Кнопка замера использует только CPU.

Режим выбирается на основном экране. GPU поддерживает 12 слов BIP39 для WalletTg и V4/V5; 24 слова TON работают на CPU. На GPU выполняются PBKDF2 и SLIP-0010; Ed25519 и проверка адресов — на CPU. В CPU + GPU оба пути независимо создают новые фразы и ищут совпадение. Половина выбранных потоков CPU проверяет результаты GPU (максимум 32), остальные ищут сами. В режиме GPU выбранные потоки CPU занимаются проверкой адресов. Счётчики суммируют реально проверенные адреса. Предел ползунка задаётся hardwareConcurrency; на этом устройстве доступно 24.

Активность GPU регулируется от 5 до 90%, по умолчанию 50%. Это программная доля работы с паузами, а не точное значение загрузки устройства. Размер порций растёт постепенно от 512 до 8192 фраз; длительность команд адаптируется. GPU можно приостановить отдельно, в фоне он отдыхает. После команды дольше 100 мс поиск GPU ждёт решения пользователя; кнопка «Игнорировать лимит времени и продолжить» действует до конца этого поиска. Проверки правильности, ошибки устройства и жёсткие таймауты остаются. При отказе GPU совместный режим продолжает поиск на CPU.

Сотни тысяч и миллионы проверок в прежнем переборе ID нельзя выдавать за скорость совместимого импорта новых фраз. Сравнительные результаты находятся в `audit/CPU-PERFORMANCE.md`. Скрипт `node scripts/benchmark-cpu.mjs` измеряет именно цикл ID, без генерации фраз.

## Секреты

Старая фраза и публичный ключ не нужны. Новые слова создаются Web Crypto внутри worker. До явного показа/копирования/сохранения победившие слова остаются в worker. Нет сетевых API, аналитики, CDN, cookies, localStorage, IndexedDB или service worker. CSP блокирует соединения страницы и worker; сервер слушает только 127.0.0.1 и отдаёт шесть статических файлов.

Сохрани полный JSON до закрытия вкладки: он содержит **секретную фразу** и параметры восстановления, без шифрования. Автосохранения и сервера восстановления нет. Контракты не разворачиваются, транзакции не подписываются и не отправляются. Доступные буферы очищаются по возможности; гарантировать стирание всех копий строк и памяти библиотек невозможно. Это ограниченная проверка кода, не полный независимый аудит устройства и зависимостей.

- `src/wallet-worker.js`, `src/tg-mnemonic.js`, `src/public-key.js`: генерация и деривация.
- `src/engine.js`, `src/fixed-sha256.js`: адреса, matcher и ускоренный SHA256.
- `scripts/build.mjs`: сборка с проверкой хешей контрактов.
- `server.mjs`: локальный статический сервер и CSP.

`src/gpu-*` содержит локальный WebGPU-код с контрольными векторами и проверкой каждого пакета. GPU запускается только после явного выбора режима и старта поиска. `audit/` содержит снимки сторонних исходников для чтения, сервер их не отдаёт. Прежние `src/app.js`, `src/index.html`, `src/style.css`, `src/worker.js` и `dist/worker.js` сохранены для старой версии с публичным ключом.
