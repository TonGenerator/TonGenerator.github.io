# GENERATOR TON USERNAME для Windows

24 октября 2026, Windows x64. Самостоятельная папка приложения: release/GENERATOR TON USERNAME. Electron 45.0.0 получен из официального GitHub релиза. SHA256 архива: ae53887a23bb640369c93dbd38c408a2af5c0deb86f2fa76c6c244cb444b7f47. Сопоставлен с официальным SHASUMS256.txt. Авторская сборка не подписана отдельным сертификатом разработчика; сторонние библиотеки закреплены в package-lock.json.

## Работа в фоне

Tray принадлежит основному процессу. Engine — отдельный скрытый BrowserWindow с contextIsolation, sandbox, выключенным Node integration и backgroundThrottling=false. Пользовательский браузер только управляет поиском и показывает публичное состояние. Закрытие пользовательской вкладки не уничтожает engine. IPC ограничен главным frame скрытого окна на точном URL engine.html. Preload экспортирует только конкретные команды/снимки состояния; произвольного выполнения JavaScript через HTTP API нет.

Автозапуск — per-user Windows Run через app.setLoginItemSettings с --background, без службы, прав администратора, изменения правил защиты или планировщика. Поиск продолжается после входа пользователя только если был начат и не остановлен. Параметры поиска и предпочтения сохраняются атомарно; запись настроек сериализована. В настройках нет секретных слов. Ярлык меню «Пуск» имеет AppUserModelID приложения для уведомлений.

## Регулировка нагрузки

Собственная CPU-нагрузка считается по разности cumulativeCPUUsage каждого процесса за измеренный интервал, делённой на число логических CPU. Это устраняет зависимость от нормализации percentCPUUsage: прежний расчёт на этом ПК ошибочно считал значительную часть генератора внешней нагрузкой. Неизвестные/сброшенные счётчики учитываются консервативно. Повторное использование PID различается по creationTime. В hybrid лимит независимых CPU worker учитывает уже занятые GPU checker-потоки; checker-порты остаются активными, их нагрузка регулируется duty.

monitor.exe использует Win32 SHQueryUserNotificationState, foreground window bounds/styles, список имён известных игр и путь foreground-приложения для Steam/Epic. GPU Engine counters читаются через PDH English counters. Собственные PID Electron исключаются из оценки внешнего GPU. Нет чтения памяти игр, инъекций, перехватов клавиш, снимков экрана или передачи списка процессов по сети. Наружу helper отдаёт только game/fullscreen и числовую загрузку.

Основной процесс оценивает внешний CPU по системной загрузке и app.getAppMetrics, учитывает питание и задержку управляющего цикла. Прежние ступени по длительности простоя (2 потока/12% CPU/5% GPU при использовании ПК) заменены непрерывным бюджетом. Рост duty — не более 8 процентных пунктов в секунду, уменьшение до доступного бюджета сразу. GPU может достигать выбранных 90% программного duty и во время работы за ПК. Внешняя активность GPU вычитается из бюджета 92%; внешний CPU — из бюджета 85% при активном вводе и 95% в простое. При активном вводе до двух логических потоков оставляются за пределами лимита поиска; это запас по бюджету, не закрепление физических ядер. Пониженный приоритет процессов сохранён. CPU/GPU бюджеты снижаются независимо; поздний tick дополнительно уменьшает оба. Задержка main event loop — косвенный сигнал перегрузки, не измерение FPS или задержки ввода другой программы.

Игры, fullscreen, внешняя нагрузка CPU/GPU выше 85%, задержка tick более 750 мс, батарея, сон или устаревшие данные монитора приостанавливают поиск. После игры — 20 секунд ожидания, после краткой перегрузки — 3 секунды. CPU duty регулируется в worker; вычисления регулярно уступают event loop, чтобы управляющие сообщения принимались. GPU получает паузу и новый duty. Проверяющие seed worker также поддерживают паузу. Их таймаут считает только активное время, поэтому длительная игра не вызывает ошибку таймаута проверки.

Скрытие пользовательского браузера не ставит поиск на паузу. Блокировка экрана допускает расчёт в простое, но уведомление откладывается до разблокировки. Сон приостанавливает расчёты. Проверяются условные сигналы игр/fullscreen и реальные показания Windows на этом компьютере. Для всех игр и драйверов отсутствие влияния на FPS не подтверждалось. Невозможно гарантировать немедленное обнаружение любой оконной игры; помогают внешние GPU counters и перечень процессов. При неизвестном/неработающем мониторе действует пауза.

## Результаты и локальный API

В интерфейс добавлено среднее ожидание до совпадения и сроки для шансов 50%/95%. Скорость для оценки берётся по реальным приращениям счётчика за последние примерно 10 секунд, с разогревом не менее 2 секунд; пауза, перезапуск и потеря связи сбрасывают замер. Вероятность модели — 1/64 на точный символ, 2/64 на латинскую букву без учёта регистра. Для шанса q используется целое число проверок ceil(log(1-q)/log(1-p)); среднее 1/p. Уже потраченные проверки не вычитаются из ожидания нового случайного совпадения. Это вероятностная оценка при постоянной текущей скорости без будущих пауз, не гарантия срока. Четыре теста проверяют вероятности, формат длительности, смену скорости и сброс после пауз/перезапусков. Изменены только статические файлы dashboard: native engine не перезапускался.

Победитель повторно проверяется каноническим CPU-путём. Для автоматической резервной копии слова передаются из winner worker в изолированный engine и далее через ограниченный IPC в main, где сразу шифруются safeStorage (Windows DPAPI). Строки/доступные массивы очищаются по возможности; гарантии физического удаления всех копий JS/WASM нет. JSON на диске содержит ciphertext. Открытые слова не пишутся в настройки, статус, уведомления или логи. При отказе записи новая генерация/выход блокируются до защищённого сохранения или явного экспорта секретного JSON.

API слушает IPv4 loopback; Host строго 127.0.0.1:11111. POST требует точный Origin, SameSite=Strict HttpOnly cookie, CSRF nonce и JSON. Cross-site API запросы отклоняются, CORS не включён. engine.html имеет отдельный случайный credential, передаваемый только скрытому BrowserWindow. CSP engine запрещает connect, CSP UI разрешает только self для HTTP API. Внешние запросы engine дополнительно блокируются через webRequest. Действия раскрытия/экспорта — POST; ответ no-store. Экспортированный пользователем JSON содержит открытые секретные слова.

DPAPI привязан к Windows-профилю и локальному ключевому материалу Chromium. Необходимо экспортировать резервный JSON перед переустановкой ОС/переносом. Другие программы того же Windows-пользователя, вредоносные расширения браузера и компрометация ОС находятся вне этой защиты. Порт не публикуется в LAN и не пробрасывается в интернет.

## Проверка

Отдельный smoke-профиль в test-results/desktop не регистрирует автозапуск. На реальной Windows проверены: engine ready, живой native monitor, доступность WebGPU, работа сервера, Tray, DPAPI encrypt/decrypt round-trip и поддержка уведомлений. Расширенный smoke запустил настоящий GPU-поиск WalletTg по короткому тестовому окончанию: найденный кошелёк сохранён, расшифрован обратно, адрес/число слов совпали. На диске не было открытой фразы. Windows приняла тестовое уведомление. Тестовые слова не выведены и не экспортированы в открытый файл.

Unit/integration проверки охватывают governor и его задержку после игр, пределы профилей, HTTP Host/session/CSRF/Origin, приватный engine URL, паузу/resume CPU worker и прежние проверки TON-адресов. Реальная перезагрузка компьютера не выполняется; запись автозапуска проверяется отдельно после обычного запуска. Настройки Windows уведомлений могут подавить показ, даже если API принял уведомление.

Итог после обновления: все 48 отдельных тестов прошли; два HTTP-теста потребовали повторного запуска вне песочницы из-за EACCES на localhost. Сборка и UTF-8 изменённых файлов проверены. Обычная сборка обновлена и запущена в трее. В 30-секундном реальном поиске Telegram WalletTg, hybrid, 24 потока и предел GPU 90% проверены 364 519 адресов. После подготовки интервальная скорость была 12 870–14 488 адресов/с, без пауз и ошибок. Собственный CPU отделён от внешнего (в последнем образце 36% и 6%). Это короткий замер, а не доказательство отсутствия влияния на FPS. Публичные измерения без слов — test-results/desktop-adaptive-performance.json. После проверки поиск возвращён в исходное остановленное состояние. Найденные кошельки не раскрывались. Подтверждённые ранее HKCU Run и ярлык «Пуск» сохранены.
