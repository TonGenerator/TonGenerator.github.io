# Проверка TonSuite и локального генератора

> Этот отчёт описывает сохранённую версию TonSuite и прежний локальный генератор с вводом публичного ключа. Текущий интерфейс создаёт новые сид-фразы; его отдельная проверка находится в [NEW-WALLET-SECURITY.md](NEW-WALLET-SECURITY.md). Утверждения ниже об отсутствии генерации секретов и публичном JSON относятся только к прежней версии.

Дата: **23 октября 2026**, часовой пояс Asia/Krasnoyarsk.

## Вывод

В просмотренных путях генерации загруженной версии TonSuite **не обнаружено явной отправки сид-фраз, приватных ключей или seed на сервер**. Это результат ограниченного статического просмотра, **не доказательство отсутствия закладок и не гарантия безопасности сайта**.

В локальном приложении TonSuite не используется. Для перебора walletID достаточно публичного ключа: сид-фраза и секретный ключ не создаются и не вводятся. Поэтому их невозможно украсть именно из входных данных этого генератора.

## Найденные пути работы с секретами

1. `tonsuite-worker.js`: функции `Ve`, `He` создают BIP39-энтропию через `crypto.getRandomValues`; `Je`, `nt` используют тот же источник для 24-словных TON-мнемоник. В просмотренном генераторе нет замены этого источника на `Math.random` или фиксированный seed. См. readable/tonsuite-worker.js:3286–3395.
2. CPU/GPU-ветки создают мнемонику, получают seed через PBKDF2, выводят Ed25519-ключ, формируют адрес и проверяют окончание. Победитель повторно сверяется CPU-путём с TON SDK. `walletCandidateFromMnemonic` находится в конце `tonsuite-ton.js`.
3. Фразы хранятся в памяти worker. Сообщение `candidate` передаёт интерфейсу адрес и метаданные; сообщение `reveal` отдаёт победившую мнемонику основной странице. `postMessage` здесь является локальной передачей между worker и страницей, а не сетевым запросом.
4. При завершении/отбрасывании вариантов код обнуляет некоторые буферы и массивы. Это полезная мера, но строки JavaScript и их копии нельзя гарантированно стереть из памяти. Кнопка копирования фразы явно записывает её в буфер обмена.

## Сеть и постоянное хранение

- В `tonsuite-index.js` найдены загрузка module-preload, локальных стикеров `/generator/stickers/*.tgs` и общий XMLHttpRequest-загрузчик анимаций. Просмотренные вызовы не передают туда мнемоники.
- В `tonsuite-ton.js` присутствуют axios, TonClient и HTTP API из общего SDK. Поэтому утверждение «в файле нет сетевого кода» было бы неверным. Просмотренный путь генерации использует локальную сериализацию и хеширование; явного вызова HTTP-клиента с seed/мнемоникой в этом пути не обнаружено.
- `libsodium-wrappers` содержит общий XMLHttpRequest-загрузчик WASM. В полученном файле WASM встраивается в JavaScript как base64 и передаётся в WebAssembly. Его бинарный код не прошёл независимый аудит. Проверка одного тестового вектора Ed25519 не доказывает отсутствие закладки для других входов.
- В просмотренном коде приложения не найдены пути сохранения мнемоник в localStorage, sessionStorage, IndexedDB или cookies. Динамического сетевого перехвата исходного сайта не проводилось.
- CSP в HTML TonSuite содержит `connect-src 'self'`: соединения с собственным доменом разрешены. Сервер способен выдать другой JavaScript при следующем открытии; проверка снимка не распространяется на будущие версии или целевую подмену.

## Что остаётся непроверенным

Не выполнялся полный криптографический аудит библиотек, WASM, GPU-шейдеров, генерации энтропии и стандарта деривации для всех вариантов. Не подтверждалась эквивалентность собранных файлов исходному репозиторию. Не проверялись сервер, DNS, инфраструктура доставки, расширения браузера, ОС и сторонние программы. Отсутствие видимого запроса не исключает предсказуемую генерацию ключей: именно поэтому локальная версия не создаёт ключи вообще.

## Защита локального приложения

- Собственная реализация сериализации V4R2; хеширование из закреплённой `@noble/hashes@1.8.0`, локально включённой в сборку. TON SDK нужен при сборке и в проверках и не попадает в браузер целиком.
- Только публичный ключ в HEX. Нет получения ключа из сид-фразы, подписи транзакций или подключения кошелька.
- `connect-src 'none'`, `default-src 'none'`, скрипты/стили/worker только с локального origin, `form-action 'none'`, `frame-ancestors 'none'`.
- Сервер слушает `127.0.0.1`, ограничивает Host и разрешает только GET/HEAD пяти статических файлов. Каталоги исходников, audit и node_modules через него недоступны. CSP возвращается также для worker.
- Никакого постоянного браузерного хранилища. JSON скачивается только по явной кнопке и содержит публичные параметры.
- Это не абсолютная изоляция от сети на уровне ОС. Пользовательское расширение, заражённый компьютер или подменённые локальные исходники выходят за границы этой проверки.

## Проверено на локальной версии

- Сравнение raw-адресов с официальным `@ton/ton@16.0.0`: случайные ключи, walletID 0, 1, стандартный ID, границы знакового int32, 4294967295 и 30 случайных ID.
- Совпадение UQ/EQ и testnet/mainnet с SDK, CRC16 и обратный разбор адреса.
- Разделение uint32-пространства между потоками, отсутствие пересечений при переходе через ноль.
- Сопоставление начала/окончания, регистра, публичный экспорт и отклонение некорректного ввода.
- HTTP-запрет приватных файлов, POST и постороннего Host; наличие CSP.
- В браузере: поиск окончания `ton`, остановка длительного поиска, точный префикс `A` после четырёх символов в bounceable testnet-адресе, повторная проверка результата.

Дополнение после ускорения CPU: CRC16 переведён на таблицу, добавлена предварительная проверка символов по битам хеша без формирования полной строки адреса. Хеширование всех walletID, контракт, сеть и ключи не изменены. Новые проверки сравнивают быстрый matcher со строками, полученными от TON SDK, для всех длин шаблона 1–8, границы hash/CRC, начала/окончания, обоих регистров и четырёх форматов адреса. Табличный CRC16 отдельно сверен с исходным побитовым алгоритмом и вектором `123456789` → `0x31c3`. Все 6 тестовых групп проходят. Быстрый worker проверен в отдельной вкладке на демо-ключе; найденное окончание `toN` прошло повторную проверку. Текущий пользовательский поиск не останавливался.

Ограничение продукта: нестандартный walletID должен поддерживаться кошельком, который подписывает транзакции. Обычного восстановления сид-фразы может быть недостаточно для открытия найденного адреса. Демо использует публично известный тестовый ключ RFC 8032 и не предназначено для средств.

Официальное описание [Wallet V4](https://docs.ton.org/standard/wallets/v4) и [связи public key, walletID и адреса](https://docs.ton.org/standard/wallets/how-it-works).
