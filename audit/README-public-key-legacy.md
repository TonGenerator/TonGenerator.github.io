# walletID lab

Локальный генератор красивых TON-адресов Wallet V4R2. Перебирает walletID (uint32) с одним публичным ключом. Не генерирует и не принимает сид-фразы или приватные ключи.

## Открыть сайт

Двойной щелчок по `Открыть генератор.cmd`. Или из этой папки:

```powershell
npm start
```

Адрес: http://127.0.0.1:4173/

Готовая сборка в `dist/`. Для её запуска интернет не нужен. Для пересборки после изменений: `npm run build`. При переносе исходников на другой компьютер сначала `npm ci --ignore-scripts` (потребуется интернет), затем `npm run build`. Установка зависимостей не запускает их установочные скрипты.

## Использование

1. Укажи свой **публичный ключ** — 64 HEX-символа. Это не адрес UQ/EQ и не сид-фраза. Его можно получить из данных своего активного кошелька (`get_public_key`) или доверенного кошелька. Сайт не получает его через сетевые API.
2. Выбери окончание либо начало адреса после первых четырёх символов, регистр, сеть и формат.
3. Запусти поиск. Потоки не повторяют диапазоны. Можно остановить в любой момент; новый запуск начинает полный диапазон со случайной позиции.
4. Скачай JSON. В нём только публичные параметры. Сохрани walletID, publicKey, сеть и версию контракта.

**До пополнения проверь, что твой кошелёк умеет использовать нестандартный walletID V4R2.** Обычный импорт той же сид-фразы может открыть другой адрес. Каждый walletID — отдельный аккаунт со своим балансом. Этот инструмент не подписывает транзакции и не разворачивает контракт. Смена флага testnet влияет на формат адреса, но не обеспечивает V4R2 защиту подписей от повторного воспроизведения между сетями.

Кнопка демо использует тестовый публичный ключ RFC 8032. Его приватный ключ известен всем: **демо-адреса нельзя пополнять**.

## Скорость и границы

На вариант нужны два SHA-256 и формирование адреса с CRC16. PBKDF2 и генерации ключей в переборе нет. Используется локальная копия `@noble/hashes@1.8.0`, без WASM и внешних загрузок. Параллелизм — Web Workers.

На этом компьютере один поток Node проверял примерно 118 тыс. вариантов/с; в браузере четыре потока — примерно 325 тыс./с (замер около 58 секунд). Это измерение, не обещание скорости; прямого сравнительного бенчмарка с TonSuite не проводилось.

Обновление ускорения CPU: шаблон предварительно проверяется по битам хеша; строка адреса создаётся только для найденных результатов и редких обновлений прогресса. CRC16 считается по таблице, а для длинного окончания — только после проверки части шаблона в самом хеше. Все walletID по-прежнему проверяются, вероятность совпадения не меняется.

Сравнение исходного и ускоренного алгоритма: `node scripts/benchmark.mjs`. Медиана четырёх чередующихся замеров по 120 000 вариантов в одном потоке Node на этом компьютере:

| Шаблон | До, вариантов/с | После, вариантов/с | Ускорение |
| --- | ---: | ---: | ---: |
| `_FURRY`, точный регистр | 123 635 | 193 562 | 1,57× |
| `cafe`, без учёта регистра | 119 094 | 187 833 | 1,58× |
| `a`, без учёта регистра | 131 068 | 185 819 | 1,42× |

Это сравнение одного потока Node; фактическая скорость браузера и масштабирование на потоки могут отличаться. Ускоренный worker загружается при новом запуске поиска. Уже работающий поиск продолжает выполняться прежним кодом: обновлять страницу во время него не нужно, иначе прогресс будет потерян. GPU-ускорение в этой версии не реализовано.

Всего доступно 4 294 967 296 walletID. Для длинного шаблона совпадения может не быть. Вероятность в интерфейсе предполагает равномерное распределение хешей. Окончание включает контрольную сумму: UQ/EQ и testnet/mainnet влияют на совпадение. Начало ищется с индекса 4, чтобы исключить ограниченные служебные символы.

## Проверки и защита

- `npm test`: совпадение с официальным TON SDK для случайных ключей, крайних uint32 и всех четырёх форматов; разделение диапазонов; matching; ограничения локального сервера.
- Сборка сверяет хеш кода V4R2 с опубликованным `feb5ff6820e2ff0d9483e7e0d62c817d846789fb4ae580c878866d959dabd5c0`.
- Сервер слушает только 127.0.0.1, ограничивает Host, разрешает GET/HEAD только для пяти статических файлов.
- CSP запрещает сетевые API (`connect-src 'none'`) и внешние скрипты. Это ограничение API браузера, не абсолютная изоляция устройства.
- Нет аналитики, внешних шрифтов, CDN, localStorage, cookies, IndexedDB и service worker. Результат хранится в памяти вкладки, экспорт — по нажатию кнопки.
- Исходники TonSuite не используются в локальном приложении и не отдаются сервером. Они лежат отдельно в `audit/` только для проверки.

## Файлы

- `src/engine.js`: сериализация V4R2, CRC16, формат адреса и поиск.
- `src/worker.js`: полный перебор uint32 отдельными непересекающимися потоками.
- `src/app.js`: интерфейс и повторная проверка найденного адреса.
- `server.mjs`: статический сервер и заголовки защиты.
- `audit/REPORT.md`: ограниченная проверка загруженной версии TonSuite.
- `audit/sha256.json`: SHA-256 сохранённых исходных файлов TonSuite.

Документация TON: [V4](https://docs.ton.org/standard/wallets/v4), [как устроены кошельки](https://docs.ton.org/standard/wallets/how-it-works).
