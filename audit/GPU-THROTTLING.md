# GPU и CPU + GPU: проверка 23 октября 2026

WebGPU выбирает high-performance adapter. На этом компьютере браузер возвращает `nvidia pascal`, установлен GTX 1060 6GB. Выбранное устройство показано под режимом поиска. Процент активности задаёт программные паузы; это не команда драйверу держать точное использование GPU.

## Что изменено

- PBKDF2-HMAC-SHA512 2048 и SLIP-0010 `m/44'/607'/0'` выполняются на GPU. Полный 64-байтовый BIP39-root и итоговый seed проверяются контрольными векторами.
- SHA512 использует четыре раунда в runtime-группе и 16 именованных регистров расписания. Полное разворачивание 80 x 2048 раундов не применяется. Общая таблица SHA-констант в read-only GPU storage заменяет частную таблицу на каждую фразу.
- Порции растут с 512 до 8192 фраз; число PBKDF2-итераций в одной команде адаптируется от 1 до 256. В очереди устройства одна команда за раз. Короткие периоды простоя накапливаются, чтобы 4-мс ограничение браузерных таймеров не умножало каждую короткую паузу.
- Подготовка следующей порции перекрывается с проверкой предыдущей. Хранится максимум одна текущая и одна подготовленная порция. Находящиеся в подготовке секреты очищаются и при нахождении результата, и при отмене/ошибке.
- Ed25519 и проверка адресов работают в CPU-checker через приватные MessagePort. Повторно используются буферы StateInit/SHA256 при смене публичного ключа. Число проверяющих потоков задаётся выбранным бюджетом CPU: все в режиме GPU, половина в совместном режиме, максимум 32 проверяющих потока.
- CPU + GPU дополнительно ведёт независимый CPU-поиск новых фраз. Суммируются фактические адреса; контрольные векторы и неподтверждённая подготовленная порция не прибавляются к проверенным адресам.

## Управление

CPU остаётся режимом по умолчанию. GPU доступен для BIP39-12 в WalletTg, V4R2 и V5R1. TON-24 работает на CPU. Активность регулируется 5–90%, исходное значение 20%. Ползунок действует во время поиска. Отдельная пауза/скрытие вкладки приостанавливают GPU; CPU в совместном режиме продолжает работу.

После завершившейся команды дольше 100 мс GPU ждёт решения. Кнопка «Игнорировать лимит времени и продолжить» снимает только этот лимит на текущий запуск. Уже завершённая команда не повторяется. Ошибки устройства, 3-секундное ожидание GPU-команды и криптографические проверки остаются. Медленная компиляция имеет отдельный таймаут. В этой сессии кнопка была проверена на реальной 155-мс команде: счётчик GPU продолжил расти с 338944 до 404480. После отдельной паузы GPU остался на 404480, CPU вырос с 219274 до 262086.

## Замеры и границы

Ранний вариант при 20%: около 119 адресов/сек GPU. Вариант с именованными регистрами, GPU 90%, два CPU-checker, без независимого CPU-поиска: 1023488 проверенных адресов WalletTg, около 6299/сек по времени после подготовки GPU. Эти режимы имеют разную активность; отношение скоростей не является чистым сравнением одного алгоритма.

После перекрытия GPU/CPU и повторного использования StateInit, но ещё с одним checker: совместный режим за ~29 секунд проверил 214261 адрес (CPU 26357, GPU 187904), около 7181/сек. Последующие настройки с несколькими checker требуют отдельного замера. Другие приложения и вкладки пользователя во время проверки не останавливались.

Короткая проверка окончательного распределения 8 потоков CPU (4 самостоятельных + 4 checker), GPU 90%: 57558 проверенных адресов (CPU 4310, GPU 53248), около 6297/сек, ~9 секунд. Этого недостаточно для вывода об устойчивом выигрыше над распределением с одним checker. Ползунок в браузере подтверждён до 24 потоков. Загруженность GPU за отдельные снимки менялась от 2–4% до 57–62%; точные 90% аппаратной загрузки не достигнуты и не заявляются.

Итоговый GPU-поиск WalletTg с коротким тестовым окончанием нашёл адрес после 281 фактической проверки. Контрольные BIP39/SLIP-0010 векторы, случайный образец и повторное CPU-восстановление победителя прошли; 12 слов остались скрыты. Следующая подготовленная порция была отменена при завершении. `npm test`: 34/34 успешно, включая сравнение повторно используемого hasher с каноническим для трёх контрактов и обеих сетей. UTF-8 проверен.

Короткий отдельный Node-замер 2048 проверок Ed25519 + WalletTg StateInit одним CPU-checker: около 7675/сек. Это подтверждает возможный предел CPU-стадии; такая скорость не является скоростью генерации новых фраз. GPU может простаивать в ожидании CPU, даже при заданных 90% активности. Сотни тысяч совместимых адресов/сек в этой сессии не достигнуты.

Фразы остаются в worker; контрольные и тестовые слова не выводятся и не сохраняются. Победитель проверяется заново стандартным CPU-путём. Фактический импорт нового неразвёрнутого WalletTg сервером Telegram не выполнялся. Аппаратный лимит мощности/температуры не задаётся, отсутствие лагов не обещается.
