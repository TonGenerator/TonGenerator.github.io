# Проверка Vanity Local

Дата: 23 октября 2026. Область: локальная сборка CPU/GPU/CPU + GPU, BIP39-12 и TON-24, V4R2/V5R1/WalletTg. Старый `REPORT.md` относится к прежней версии и снимку TonSuite.

## Совместимость Tonkeeper

Текущий интерфейс задаёт importTarget=tonkeeper, strategy=standard и запрещает custom walletID. Engine дополнительно отвергает нестандартный ID при экспорте такого результата. Официальные значения: V4R2 698983191; V5R1 mainnet 2147483409, testnet 2147483645. Фразы BIP39-12 используют PBKDF2-HMAC-SHA512 2048, пустую passphrase и SLIP-0010 Ed25519 m/44'/607'/0'. TON-24 использует каноническую @ton/crypto 3.3.0.

Фактический пользовательский импорт в установленный Tonkeeper не выполнялся; совместимость проверена по исходникам и независимому восстановлению адреса в тестах.

## WalletTg

Официальная схема: 12 слов BIP39, тот же SLIP-0010 путь, начальные anchor/signing keys совпадают, ID mainnet 0x7FFF7F11. Initial data: revision uint8=0, seqno uint32=0, subwalletId uint32, publicKey bits256, всего 328 бит. Trampoline hash 9149ae51c1e4689710cebf7830297b16acfbadb363a920a537893e7ffeeca768, depth 0. Фиктивная 24-словная ротация не создаётся.

Источники: [интеграция](https://docs.ton.org/contracts/standard/wallets/telegram/integrate), [контракт](https://docs.ton.org/contracts/standard/wallets/telegram/contract). Формат проверен; приём нового неразвёрнутого аккаунта сервером Telegram не проверялся. Restore current wallet отличается от Import an Existing Wallet. Сам генератор аккаунт в Telegram не заменяет.

## Криптография и сеть

Случайность — Web Crypto getRandomValues. Для Ed25519 и параллельного PBKDF2 BIP39 используется закреплённая libsodium-wrappers-sumo 0.7.15 с локальным WASM; fallback — Web Crypto/TON SDK. Сборка включает WASM, не скачивает его с CDN. script-src разрешает wasm-unsafe-eval, но не JavaScript eval. connect-src none блокирует сетевые API страницы и worker.

GPU возвращён отдельным явно выбираемым режимом с компактными runtime-циклами WGSL. До старта GPU-поиска устройство и shader не создаются. PBKDF2-HMAC-SHA512 2048 и стандартный SLIP-0010 путь рассчитываются на GPU, Ed25519 и StateInit — в CPU-checker. Сначала проверяются фиксированные BIP39-root и SLIP-0010 векторы. Первый элемент каждой случайной порции сравнивается с каноническим CPU-ключом; победитель целиком выводится повторно обычным CPU-путём. Ошибка вычислений всегда останавливает GPU. Пакеты seed передаются по MessagePort напрямую между worker, в main thread попадают только публичные данные.

Максимум 8192 фразы на порцию; начальный размер 512. В очереди только одна команда с ожиданием завершения; затем регулируемая пауза 5–90%. Короткие паузы накапливаются, чтобы 4-мс ограничение браузерных таймеров не превращало 90% в низкую активность. GPU отдыхает при скрытой вкладке и ручной паузе. Команда дольше 100 мс ставит GPU на паузу с кнопкой явного продолжения без этого лимита на текущий поиск. Завершённая команда не исполняется повторно после продолжения. Не отключаются контрольные векторы, проверки ключей, ошибки устройства и жёсткий таймаут ожидания команды. Нагрузка является программным duty cycle; ограничения температуры/мощности драйвером не задаются, отсутствие лагов не гарантируется.

CPU + GPU имеет независимые CPU-search и GPU lanes; публичные счётчики суммируются. Первый проверенный победитель удерживается в своём worker, остальные останавливаются. Пауза/отказ GPU не прерывает CPU; общая кнопка стоп прекращает все потоки. Замер производительности в дополнительных настройках использует только CPU.

Для перекрытия GPU и CPU допускается ровно одна следующая порция в подготовке. При остановке/победителе GPU отменяется, следующая порция дожидается завершения очистки и её слова/seed стираются по возможности. Предварительная генерация увеличивает число созданных фраз, но не счётчик проверенных адресов. Подготовленные слова не передаются странице.

Ускоренный SHA256 применяет существующую compression-функцию закреплённой @noble/hashes 1.8.0, повторное использование padding/state/output. Сравнение со стандартным SHA256 и TON SDK охватывает все три контракта, границы ID и случайные ключи. Победитель повторно проверяется стандартной деривацией ключа и обычным хешированием StateInit.

Слова до reveal находятся в worker; прогресс и результат содержат только публичные данные. JSON/clipboard доступны по кнопке. Нет постоянного браузерного хранения. JSON содержит секреты без шифрования. Строки JavaScript, копии библиотек и память WebAssembly гарантированно стереть нельзя; доступные буферы очищаются. Подписей, переводов и развёртывания контрактов нет.

Сервер слушает 127.0.0.1, проверяет Host, разрешает GET/HEAD шести статических файлов. Исходники, audit, node_modules не доступны. CSP запрещает внешние скрипты и соединения. Нет аналитики и сторонних шрифтов. Вредоносные расширения, ОС и подмена локального кода вне этой проверки.

## Проверки

Тесты проверяют независимую BIP39/SLIP-0010 деривацию через OpenSSL, точную сериализацию WalletTg, V4/V5 по TON SDK, matcher и CRC16, ограничения Tonkeeper ID, отсутствие слов до reveal, валидность фраз и точное восстановление каждого найденного адреса. Дополнительно проверяются границы активности GPU, паузы/отмена, явное снятие временного лимита без повторного исполнения команды, бюджет потоков CPU + GPU, точные публичные результаты и очистка seed-буфера CPU-checker для всех трёх контрактов. Тестовые фразы не печатаются и не сохраняются.

Сборка фиксирует хеши V4R2 feb5ff6820e2ff0d9483e7e0d62c817d846789fb4ae580c878866d959dabd5c0, V5R1 20834b7b72b112147e1b2fb457b84e74d1a30f04f737d4f62a668e9552d2b72f и WalletTg выше.

Это ограниченная проверка просмотренного кода и функциональные тесты. Полный независимый аудит криптографии, бинарников зависимостей, драйверов и цепочки поставки не проводился.
Итоговая проверка: 34/34 теста успешно; GPU-векторы, случайные образцы, канонический победитель WalletTg, отдельная пауза и снятие временного лимита дополнительно проверены в браузере. Замеры и ограничения: GPU-THROTTLING.md.
Новый CPU PBKDF2 проверен против OpenSSL для 21 сочетания длины ключа и итераций (1/2/2048), включая ключи 0–128 байт. Используются raw HMAC-примитивы закреплённой libsodium; кешируется и клонируется начальное HMAC-состояние, затем все выделенные WASM-буферы очищаются в finally. Замеры: CPU-PERFORMANCE.md. Общая очередь WebCrypto обходится локальным WASM в каждом worker. Параметры BIP39 и проверка победителя не менялись.
